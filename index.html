Can machine learning spot a hazardous asteroid?

Team project on classifying 90,836 NASA near-Earth object records, with imbalance handling and explainable AI. Our question: how much of NASA’s hazard label can ML recover from four simple measurements, and why not more?

Pythonpandasscikit-learnSMOTESHAPKaggle: NASA Nearest Earth Objects
90,836records, no missing values
9.3 : 1non-hazardous to hazardous
54.37%best F1, RF + SMOTE
97.57%best recall, Decision Tree

Why this project

Real stakesPlanetary defenceAsteroid impacts are rare but high-consequence, so spotting dangerous objects early matters.
ML challengeOnly 1 in 10 is hazardousThe 9.3 : 1 imbalance makes accuracy misleading and forces smarter evaluation.
ExplainabilityDoes it reason like an astronomer?SHAP lets us check the model’s reasoning against physics.

“NASA already does this”

NASA / JPL CNEOS: physics-first
  • Tracks orbits from telescope data
  • Computes MOID and impact odds (Sentry)
  • Needs repeated observations of each object
Our project: data-first
  • Learns the label from 4 quick measurements
  • Tests how far ML gets without orbit data
  • Explains every decision with SHAP

We don’t replace NASA. We measure what data alone can learn, and show exactly where it hits a wall.

What made our study different

01A fair test of imbalance fixesClass weighting vs SMOTE, both scored on the same untouched test set of 18,168 records.
02A leakage-safe pipelineScaling and SMOTE fitted on training data only, and inside every cross-validation fold.
03Explanations checked against physicsSHAP’s top feature, object size, matches NASA’s own H ≤ 22 rule.
04We found the ceiling, and whyNo model passes 62% precision. We traced it to one missing feature: MOID.

The data

SourceKaggle, NASA Nearest Earth Objects (neo_v2.csv). 90,836 close approaches, no missing values.
Inputs (4)est_diameter_min (km), relative_velocity (km/h), miss_distance (km), absolute_magnitude (H).
Targethazardous (0 / 1). 8,840 records (9.73%) are hazardous; 81,996 (90.27%) are not.
Droppedid, name and est_diameter_max. The max diameter is an exact multiple of the min, so r = 1.00.
CorrelationsDiameter and absolute magnitude: r = −0.56. The relationship is exact but curved, so Pearson’s r understates it. Velocity and miss distance add mostly independent information (|r| ≤ 0.35).

What “hazardous” means. NASA needs two facts: size (H ≤ 22.0, roughly 140 m or larger) and orbit (MOID ≤ 0.05 au, within about 7.5 million km of Earth’s orbit). Our data holds the size, but not the orbit. miss_distance is one fly-by, not MOID.

Method

  1. Load neo_v2.csv
  2. Select 4 features + target
  3. Stratified 80 / 20 split, seed 42
  4. StandardScaler, fit on train only
Experiment AClass weightingLogistic Regression, Random Forest, Decision Tree, KNN and Linear SVM with balanced class weights.
Experiment BSMOTESynthetic hazardous samples on training data only: 65,596 : 65,596.
Experiment CTuned pipelineScaler → SMOTE → Random Forest inside each CV fold, using RandomizedSearchCV.

The test set (18,168 records, 1,768 hazardous) was split off first, never resampled, and used only for final scoring.

The accuracy trap

90.27%accuracy of “always safe”, catching 0 of 1,768 hazards
8%recall of the first unweighted Logistic Regression, at 90.33% accuracy
93.21%recall after class weighting, 11× more hazards caught, at 78.59% accuracy

So every model is judged by recall, F1 and MCC, not accuracy.

Baseline results (class-weighted, test set)

Recall: hazards caughtPrecision: alarms that are real

Catch-everything: Decision Tree, Logistic Regression and Linear SVM flag nearly every large object, with recall above 93% and precision near 31%. Cautious: Random Forest and KNN raise few alarms but miss about 1,140 of 1,768 hazards.

Class weighting vs SMOTE

ModelChange in F1 with SMOTEWhy
Random Forest+9.40 points ★F1 44.97% → 54.37%. Recall 35% → 62%, 462 more hazards caught.
KNN+7.83 pointsIt had no balancing before.
Logistic Regression+0.02Both methods shift the same decision boundary.
Linear SVM0.00
Decision Tree−0.15

The wall at 62% precision. Across all 11 models, none passes 61.6% precision. The six high-recall models sit near 31%. This is not an algorithm weakness. Size is in the data, MOID is not, so among large objects no model can tell whose orbit comes close to Earth.

Explainable AI with SHAP

Mean |SHAP| for Random Forest + SMOTE on 300 test records. The model judges by size, just like NASA’s rule.

82% of the model’s reasoning is object size (diameter + magnitude), the same thing NASA’s H ≤ 22 rule checks.

One asteroid, explained: about 82 m across, H ≈ 22.6, just above the 22.0 cut-off

Final score 0.00: not hazardous (correct). SHAP explains the model’s behaviour. It does not prove causation.

What this changes

Fast first-pass screeningCatches 97.6% of hazards from size alone, with no orbit fit. Could help rank new objects for follow-up.
Shows what data is neededSize-only data caps precision near 62%. Future models must add orbital features such as MOID.
Explainable, trusted AISHAP shows the decisions follow physics, not noise.
A reusable templateStratified split, SMOTE inside CV and MCC carry over to fraud, disease or defect detection.

Conclusion and next steps

Random Forest + SMOTE gave the best balance (F1 54.37%, MCC 0.492). If the goal is to catch as many hazards as possible, the Decision Tree is best: 97.57% recall with only 43 hazards missed.

  1. Add MOID and orbital elements
  2. Split by asteroid id (group split)
  3. Tune the decision threshold, report PR-AUC
  4. Streamlit app with live SHAP

Machine learning project · Wildlife conservation

Wildlife Intelligence System

This project uses a Random Forest classifier trained on data covering 154 wildlife species. The supplied report describes an interactive Streamlit app for exploring species predictions and highlights the role of animal attributes in conservation-focused classification.

These figures are taken from the project report and have not been independently re-evaluated here.

What the model considers

The report identifies geographic range, lifespan, and gestation as influential predictors. Together with the Streamlit interface, these features make the project a way to explore how species information can support conservation-related analysis.

Limitations to keep in mind

The report notes dataset size and class imbalance as limitations. Predictions based on species attributes also do not capture changing population trends, so the classifier should be treated as an exploratory project rather than a substitute for current field data or expert assessment.
